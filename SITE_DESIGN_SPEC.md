# Price Watcher — ТЗ только на сайт и дизайн

Этот документ задаёт внешний вид и поведение интерфейса. Он не определяет серверную архитектуру и расчёты. Образец внешнего вида лежит в папке `design_reference/` репозитория: снимки страниц и старые стили. Это образец того, как сайт должен выглядеть, а не код для переноса. Новая разметка, CSS и JS пишутся заново по этому документу; из образца берутся цвета, шрифты, отступы, радиусы, тени и композиция экранов. Где образец и этот документ расходятся, вопрос решает владелец.

## 1. Цель и общие правила

- Это панель мониторинга желаемых покупок и цен в российских магазинах. У каждого пользователя свой список; есть роли «пользователь» и «администратор». Элементы, доступные только администратору, обычному пользователю не показываются вовсе.
- Язык интерфейса — русский. Названия магазинов и товары показываются в оригинальном написании.
- Сайт должен выглядеть как законченный продукт и на большом мониторе, и на телефоне.
- Адаптивность не должна достигаться масштабированием всей страницы: шрифты, сетки, отступы и действия перестраиваются по ширине.
- Не показывать фиктивную цену, фиктивный успех, тестовые цифры или бесконечный индикатор загрузки.
- Все интерактивные состояния должны иметь видимый focus, hover/pressed, disabled, loading, success и error вариант.
- Классы элементов и `data-*` hooks документировать: JavaScript поведения не должен искать элементы по хрупкой структуре вложенности.

## 2. Визуальный язык

- Основной фон — очень тёмный графитовый; поверхности карточек немного светлее фона. Светлая тема тоже поддерживается через те же токены.
- Главный акцент — спокойный фиолетовый: выделенные кнопки, индикаторы, боковая линия категории и активные сегменты.
- Снижение цены — зелёный, рост — мягкий красный, отсутствие данных — нейтральный серо-синий. Цвет всегда сопровождается подписью, знаком или числом.
- Карточки с мягким радиусом, тонкой границей и умеренной тенью. Не использовать тяжёлые градиенты, большие пустые поверхности и резкие скачки стиля между страницами.
- Заголовки — выразительный геометрический шрифт; основной текст — хорошо читаемый sans-serif; цены и цифры — моноширинные цифры с выравниванием.
- Денежные суммы форматировать пробелами разрядов и знаком ₽. Не допускать склейки цифр, валюты и процентов.
- Использовать CSS-переменные для фона, поверхности, текста, вторичного текста, рамки, акцента, роста и снижения. Все магазины получают цвет из ограниченной, контрастной палитры.

## 3. Общая шапка и каркас

- Шапка содержит бренд Price Watcher, компактный статус парсера, колокольчик уведомлений (только у администратора), кнопку настроек и меню пользователя с выходом.
- Колокольчик содержит системные уведомления администратора и показывает число непрочитанных. По нажатию открывается список: текст, время, ссылка на товар или раздел; есть «Отметить все прочитанными» и пустое состояние.
- Под шапкой при необходимости показывается полоса системного предупреждения для администратора: недоступен бот, недоступен worker, устарела резервная копия.
- Шапка остаётся сверху при прокрутке, имеет полупрозрачный фон и тонкую нижнюю границу, не закрывает заголовки страниц.
- Статус: спокойная точка и текст последней проверки; в процессе — пульсирующая точка и прогресс; ошибка связи — отдельное нейтральное/красное состояние с пояснением.
- На узком экране текст статуса сокращается, но остаётся читаемым; кнопка настроек сохраняет область нажатия не меньше 44×44 CSS px.
- Контент ограничен максимальной шириной и центрируется. На телефоне остаются одинаковые боковые поля.
- Хлебные крошки короткие; на телефоне длинные промежуточные названия обрезаются многоточием, текущая страница видна.
- Уведомление появляется у нижнего края, учитывает safe area iPhone и не закрывает основные кнопки. Текст и «Отменить» в нём не обрезаются. «Отменить» доступно 3 секунды после удаления и других критичных изменений; оставшееся время видно по убывающей полоске.

## 4. Главная

### Блок общей суммы

- Широкая карточка на всю ширину контентной области.
- Содержит дату сводки, заголовок «Всё, что хочу купить», общую сумму и изменение за выбранный период.
- Справа на десктопе и ниже содержимого на телефоне — переключатель «Сутки / Неделя / Месяц / Год».
- Активный сегмент перемещается плавно внутри общей дорожки; фон дорожки не меняется от нажатия.
- При смене периода блок обновляется без полной перезагрузки: сервер присылает готовый HTML-фрагмент, JS подставляет его. Показывать короткое состояние обновления; при ошибке сохранить прежние данные и вывести сообщение.

### Категории

- Заголовок «Категории покупок» и подпись периода изменения.
- Десктоп: сетка из 2–3 карточек в строке по доступной ширине. Телефон: две компактные колонки; карточки в одной строке одной высоты.
- Карточка показывает имя, количество позиций/наблюдений, итог, изменение суммы, маленький график и самый изменившийся товар (на мобильном подробность самого изменившегося товара скрыть, если она делает карточку перегруженной).
- Состояние без истории: вместо графика коротко объяснить, когда он появится. Карточка без товаров показывает пустое состояние, а не нулевой ложный график.
- Последняя плитка «＋ Новая категория» визуально отличается пунктирной границей, оставаясь того же размера/ритма, что сетка.
- Карточку категории можно перетаскивать: удержание около 300–400 мс, карточка поднимается и слегка уменьшается/становится полупрозрачной, потенциальное место подсвечивается контуром, короткая тактильная отдача — если доступна. После отпускания показывается сохранение и затем уведомление с возможностью отмены.
- На телефоне короткое нажатие открывает категорию; перетаскивание не должно мешать обычной вертикальной прокрутке страницы. Добавить доступную альтернативу перестановки кнопками в настройках.

### Сводные показатели

- Четыре панели: «товаров отслеживается», «подешевели», «подорожали», «нет в наличии».
- Десктоп: четыре колонки; телефон: две колонки.
- Каждая панель — реальная кнопка с числом, короткой подписью и стрелкой состояния.
- Нажатие плавно раскрывает список под панелями: высота следует за содержимым, opacity меняется от 0 до 1, панель мягко приходит сверху. Закрытие работает в обратном направлении. Не обрезать длинный список.
- Одновременно раскрыта максимум одна панель. Повторное нажатие и отдельная кнопка закрытия сворачивают её. Уважать системную настройку reduced motion.
- Список использует компактные карточки товара: имя, магазин, категорию, старую и новую цену/процент. Пустое состояние — «Цены не менялись».

### Блок «Требует решения» и запуск парсера

Блок «Требует решения» видит каждый пользователь — по своим товарам: решение действует только на них (решение владельца 07.10.2026). Блок запуска парсера видит только администратор; обычный пользователь видит статус последней проверки и, если она идёт, её прогресс.

- Подозрительные изменения разбиваются на отдельные карточки с причиной, названием товара и магазина, датой проверки, значениями «было/стало» и кнопками: принять, отклонить, перепроверить сейчас (скачок цены), изменить ссылку; после действия — «Отменить» на 3 секунды.
- До решения новый подозрительный результат показан как неподтверждённый и не маскируется под нормальную цену.
- Ручной запуск показывает прогресс, проверенное количество, длительность и возможность безопасной остановки. Состояния: готово, выполняется, остановка ожидается, завершено, ошибка/worker недоступен.
- Если проверка уже идёт (плановая или запущенная другим администратором), кнопка запуска заменена индикатором «Идёт проверка: N из M». Второй запуск невозможен.

## 5. Страница категории

- Хлебные крошки, ярлык «Категория покупок», название категории, итог и сегменты периода.
- Пояснение, что входит в сумму и как работает отметка товара.
- Список товаров собран в общий блок; групповые заголовки имеют спокойный фон и визуально отделяют секции.
- Строка товара: чекбокс, имя, группа/магазин, наличие, короткий контрол количества, цена с учётом количества, изменение и действия порядка.
- Цена по карте крупная/основная, обычная — подписью «без карты …».
- На телефоне строка перестраивается в аккуратную компактную карточку: цена не попадает под имя, чекбокс остаётся слева, действия не переполняют ширину.
- Нижняя строка показывает итого. График ниже имеет понятную область чтения, дату/цену и объяснение пересчёта истории.
- Пустая категория: простое пояснение и кнопка добавления товара.
- Внизу категории — свёрнутый блок «Куплено (N)»: компактные строки с ценой и датой покупки. В итог категории не входит.

## 6. Страница товара

- Верхняя область: квадрат/адаптивный контейнер фотографии, название, категория/группа, полное название при наличии, лучшая цена, магазин и наличие.
- Без карты показывается меньшим текстом непосредственно рядом с основной ценой.
- Действия: включить/убрать из итога, изменить товар, раскрыть меню «Открыть в магазине», «Куплено», «В архив».
- «Куплено» открывает короткую форму: цена (подставлена лучшая, можно поправить), магазин, количество, дата. После сохранения — уведомление с «Отменить» на 3 секунды.
- Купленный товар: цена и дата покупки, магазин; 14 дней после покупки — строка «сейчас дешевле на …», если цена упала; действие «Вернуть в список». Архивный — пометка «в архиве» и «Вернуть в список».
- Цена не актуальна: заметная пометка «Цена не актуальна — обновите или замените ссылку» с переходом к ссылкам товара. Товар выходит из итога, отметка «в итоге» показана снятой; это та же отметка, что у остальных товаров. Если включить её снова, последняя цена учитывается, а рядом остаётся предупреждение «Цена не актуальна». Когда цена снова становится актуальной, особый режим снимается.
- Нет ни одной ссылки: товар со старой историей и графиками, пометка «Нет ссылок на магазины — добавьте ссылку» и кнопка добавления. Товар не исчезает и не удаляется сам.
- График цены строится по одному магазину и показывает цену за одну штуку; количество на него не влияет. Он имеет переключение магазинов и диапазона; выбранное состояние отмечено сегментом, линия плавно перерисовывается, при наведении/удержании появляется перекрестие и точный день.
- Ниже — сравнение цен по магазинам с цветным индикатором и история изменений. Цвет магазина не должен быть единственным различителем.
- На мобильном две нижние колонки становятся одной; сравнение не сжимается до нечитаемых подписей.

## 6а. Страница «Покупки»

- Сводка: потрачено за месяц и год, сэкономлено (или переплачено) за тот же период; переключатель периода как на главной.
- Разбивка по категориям и список покупок с датой, магазином, ценой и экономией по каждой.
- Отдельная вкладка «Архив»: товары, которые решили не покупать, с последней известной ценой и «Вернуть в список».
- Пустые состояния: «Покупок пока нет», «В архиве пусто».

## 7. Страница группы

- Заголовок категории и группы, короткое объяснение.
- Десктопная таблица: товар, цены магазинов, изменение, минимум периода.
- «Минимум периода» — самая низкая цена товара за штуку за выбранный период, с датой и магазином в подсказке. Если данных нет, в ячейке прочерк.
- Таблица может прокручиваться горизонтально, но не растягивает всю страницу.
- На телефоне таблица сменяется карточками товара с именем, лучшей ценой, изменением и ценами доступных магазинов.
- Пустой результат объясняет, что товаров в группе пока нет.

## 8. Настройки

### Навигация по вкладкам

- Единый сегмент «Товары / Категории», активная вкладка всегда заметна. У администратора добавляются вкладки «Магазины / Проверка / Пользователи».
- На телефоне вкладки прокручиваются или равномерно делят строку без выпадения текста.

### Товары

- Фильтр категорий, действие «Добавить товар», список строк товаров.
- Строка показывает учёт в сумме, имя, категорию/группу, магазины и действия: вверх/вниз, изменить, удалить.
- На мобильном все действия собраны в понятную сетку и остаются внутри карточки; удаление визуально опасное, но не доминирует.
- Форма товара открывается в диалоге/нижнем полноэкранном листе. Поля: ссылки, короткое/полное имя, категория, группа, количество.
- Для каждой ссылки видны состояния: не проверена, проверяется, цена найдена, ожидает плановой проверки, не удалось найти цену, ошибка формата, сайт отключён администратором (с текстом «Этот сайт отключён администратором»). У найденной цены — источник: «данные сайта» или «найдено на странице». Ошибка одной ссылки не стирает значения остальных.
- Диалог имеет фиксированные доступные заголовок и нижнюю панель действий; фокус попадает в первое нужное поле, Escape/кнопка закрытия закрывают его, при ошибке фокус и введённые данные сохраняются.

### Категории

- Список с именем, количеством товаров, итогом и кнопками порядка, переименования и удаления.
- Переименование редактируется прямо в строке.
- Удаление непустой категории показывает отдельное ясное подтверждение с выбором переноса или удаления товаров.
- Добавление категории отделено от списка и имеет понятную подпись.

### Магазины (администратор)

- Добавление магазина: администратор вставляет ссылку, видит найденные название и цену и подтверждает их либо отклоняет.
- Список с цветом, названием, доменом, числом ссылок, методом/статусом и пометкой цены по карте.
- Цвет и название изменяются на месте с коротким подтверждением.
- Включение и отключение — переключатель в строке магазина с коротким подтверждением.
- Удаление доступно только неиспользуемому магазину и визуально не путается с обычной кнопкой.

### Проверка (администратор)

- Время ежедневной проверки и до двух дополнительных; время указывается по Москве.
- Пороги подозрительного изменения названия и цены в процентах, срок актуальности цены в сутках.
- Каждое поле имеет подпись, допустимый диапазон и сообщение об ошибке рядом с полем.

### Пользователи (администратор)

- Список пользователей с ролью и датой входа; отключение пользователя с подтверждением.
- Создание приглашения: ссылка показывается один раз, с кнопкой копирования и сроком действия.

## 9. Подозрительные изменения и ошибки

- Решение принимает администратор. Пользователь видит на товаре последнюю подтверждённую цену и нейтральную пометку «на проверке».

- Карточка предупреждения обозначает тип: изменилось название или подозрительно изменилась цена.
- Содержит ссылку на магазин, сравнение полей, объяснение последствий и ясные действия. Образец — `design_reference/screenshots/desktop/Требует решения.png`.
- Над блоком — заголовок «Требует решения» и подпись «Цена не записана, пока вы не решите».
- Смена названия: «Было / Стало» и строка «Цена … · в графике пока …». Действия: «Это тот же товар» (основное), «Другой — заменить ссылку», «Отключить ссылку» (товар остаётся в списке, этот магазин перестаёт проверяться для него).
- Скачок цены: «Было / Стало» с процентом изменения. Действия: «Перепроверить сейчас» (основное, срочная проверка одной ссылки), «Цена верная», «Ошибка — отбросить».
- Порог в пояснении («Больше 30% …») берётся из настроек администратора, а не пишется в шаблоне.
- Принятое решение убирает карточку и показывает уведомление с «Отменить» на 3 секунды.
- Форма замены ссылки показывает результат проверки, но не отправляет новую ссылку до явного подтверждения.
- Для ожидания — spinner плюс текст, для отказа — причина и возможность повторить действие. Не блокировать всю страницу из-за одной карточки.
- Любая ошибка API показывает компактное сообщение и идентификатор инцидента, если сервер его вернул. Не показывать технический traceback.

## 10. Анимации и микровзаимодействия

- Общая длительность hover/нажатия: 140–220 мс; раскрытие панели: около 300–380 мс; перемещение активного сегмента: около 400 мс с мягким easing.
- Карточки при наведении слегка поднимаются (до 2–4 px), граница подсвечивается акцентом. На touch-устройстве hover-стиль не должен оставаться «залипшим».
- Нажатие кнопки — лёгкое сжатие до ~0.98 без изменения фона всей страницы.
- Раскрываемые списки анимируются по измеренной высоте, не обрезают строки и не сдвигают страницу рывком.
- Графики рисуются с плавной линией и спокойным появлением; не запускать бесконечную анимацию.
- Toast появляется снизу с коротким сдвигом/прозрачностью; исчезает сам; сообщение с «Отменить» держится 3 секунды и успевает принять фокус/нажатие.
- Для `prefers-reduced-motion: reduce` отключить смещения, длительные переходы и декоративную анимацию, сохранив смену состояния.

## 11. Состояния данных, обязательные для макетов

Для каждого блока макет/реализация должны иметь:

- заполненные данные;
- пустой список;
- первичную загрузку;
- длительную загрузку;
- ошибку загрузки;
- частичную ошибку (часть магазинов ответила);
- длинное название товара/категории/магазина;
- очень большие значения цены и количества;
- подозрительную цену;
- отсутствие цены, отсутствие наличия и удалённую карточку;
- цену «не актуальна» (магазин не отвечает 7 суток) и последнюю цену с причиной сбоя;
- товар «ожидает проверки» и товар «на проверке» у администратора;
- товар без ссылок со старой историей и призывом добавить ссылку;
- купленный товар (в том числе «сейчас дешевле на …» в первые 14 дней) и архивный товар;
- устаревшая цена, снова включённая в итог отметкой «в итоге» (с предупреждением);
- история цены, продолжившаяся после замены ссылки того же магазина (одна линия графика);
- цена магазина с пометкой «магазин отключён»;
- идущую проверку с прогрессом;
- конфликт правки: запись изменена в другом месте, показаны актуальные данные;
- много категорий/товаров и минимальную ширину телефона.

Никакое состояние не должно создавать горизонтальную прокрутку всей страницы, перекрывать кнопку важного действия или показывать непроверенную цену как подтверждённую.

## 12. Доступность и адаптивная проверка

- Интерактивные элементы — семантические `button`, `a`, `input`, `select`; кликабельные `div` не использовать.
- У иконок есть текстовая метка для скринридера; у поля — постоянная подпись, а не только placeholder.
- Видимая клавиатурная рамка фокуса, логичный Tab-порядок, диалог возвращает фокус туда, откуда был открыт.
- Контраст основного текста не ниже WCAG AA; цветовые изменения дублируются стрелкой/словом/числом.
- Контрольная проверка ширины 320, 375, 430, 768, 1024 и 1440 CSS px, светлой/тёмной темы, Safari iOS и Chrome desktop.
- Сравнивать скриншоты до/после; при подключении данных не менять отступы, цвета, типографику или DOM без отдельной причины.

## 13. Дизайн-контракт с backend

- Сайт получает от сервера готовые страницы и HTML-фрагменты. JS отвечает за анимации, выбор и отправку действий; он не собирает карточки из JSON, не считает суммы и не форматирует деньги.
- Деньги — целые копейки, только рубли. Сервер отдаёт и число (`price_minor`), и готовую строку (`price_text`). Для графиков: упорядоченный массив `{date, value_minor, label, status}`.
- Имена полей — `snake_case`.
- Для товара отдельно передавать `price`, `card_price`, `availability`, `checked_at`, `status`, `store`, `url`, `version` и признаки «в итог»/«на проверке»/«не актуальна».
- Фронтенд показывает известные статусы явно и имеет нейтральное состояние для неизвестного статуса, сохраняя сырой `error_id` только для интерфейсной диагностики.
- Не вкладывать непроверенные данные в исполняемый inline JavaScript. Передавать JSON безопасным способом или отдельным API-ответом.
- Изменение API не меняет структуру CSS и визуальных компонентов.

## 14. Вход и регистрация

- Страница входа: логин, пароль, кнопка «Войти». Ошибка не уточняет, что именно неверно. После превышения числа попыток показывается время ожидания.
- Страница регистрации открывается только по ссылке-приглашению: логин, пароль с подсказкой требований, повтор пароля. Недействительное или истёкшее приглашение показывает объяснение без формы.
- В настройках пользователя: подключение приложения (кнопка «Получить код», код крупными символами и обратный отсчёт 5 минут), привязка Telegram, список устройств с отзывом доступа, выход.
- Страницы входа и регистрации оформлены теми же токенами и компонентами, что остальной сайт.

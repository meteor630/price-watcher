# Правила для ИИ-разработчика

Этот файл читается первым в каждой задаче. Правила обязательны. Если правило мешает выполнить задачу, остановись и спроси владельца проекта.

## 1. Что читать

1. Этот файл.
2. `PROJECT_MAP.md` — найти модуль задачи, его зависимости и команду тестов.
3. Файлы, которые меняешь, и их тесты.
4. Прямые зависимые изменяемого модуля: `uv run python tools/deps.py <модуль>`.

Остальные файлы не читать. Весь репозиторий не перечитывать. Разделы документов плана читать только те, на которые ссылается карта для этой задачи.

Если карта расходится с кодом, сначала исправь карту, потом продолжай.

## 2. Что менять

- Только файлы, нужные задаче, и их тесты.
- Попутный рефакторинг, переименования и «улучшения» вне задачи запрещены. Заметил проблему рядом — запиши её в отчёт.
- Границы модулей описаны контрактами import-linter. Контракт меняется только с согласия владельца.

## 3. Образец дизайна

Папка `design_reference/` показывает, как сайт должен выглядеть. Старый код содержит ошибки и уязвимости.

```text
design_reference/
  screenshots/desktop/   снимки страниц на большом экране
  screenshots/mobile/    снимки страниц на телефоне
  css/                   старые стили
  html/                  старые шаблоны (необязательно)
  NOTES.md               пожелания владельца: что нравится, что переделать
```

- Брать из образца: цвета, шрифты, размеры, отступы, радиусы, тени, анимации, композицию экранов.
- Не копировать код: разметка, CSS и JS пишутся заново по `SITE_DESIGN_SPEC.md`.
- Старый JS и серверный код в репозиторий не кладутся и образцом не служат.
- Папка только для чтения; в сборку и на сервер она не попадает.
- Читать её только в задачах по интерфейсу, и только снимки и стили нужной страницы.
- Готовая страница сравнивается со снимком образца; заметные расхождения перечисляются в отчёте.

## 4. Запрещено

- Заглушки: `pass`, `TODO`, `NotImplementedError`, фиктивные возвращаемые значения, тестовые данные в рабочем коде.
- Неиспользуемые функции, параметры, файлы и код «на будущее».
- Костыли: частный `if` под один случай, `sleep` вместо ожидания события, повтор запроса вместо поиска причины, отключение проверки, подгонка кода под тест.
- Пустой `except`, перехват `Exception` без записи в журнал и повторного выброса, молчаливый запасной путь.
- Ослаблять, пропускать, удалять или переписывать тест, чтобы он позеленел.
- `float` для денег.
- Секреты в коде, логах, карте, тестах.

Если функция нужна позже, её нет в коде; она есть строкой «отложено» в `FEATURE_STATUS.md`.

## 5. Исправление ошибки

1. Воспроизведи ошибку падающим тестом. Не получается — остановись и опиши, что пробовал.
2. Найди первопричину и назови её в отчёте одной фразой.
3. Исправь причину там, где она возникает.
4. Убедись, что новый тест зелёный, и прогони тесты по разделу 7.

Исправление без воспроизводящего теста не принимается.

## 6. Когда остановиться и согласовать

Остановись, опиши проблему и варианты, жди решения владельца, если:

- требование неоднозначно или противоречит документам;
- задача не решается без нарушения раздела 4;
- нужно отойти от утверждённого плана, схемы базы, контракта API или границ модулей;
- обязательный тест красный, и причина не в твоём изменении;
- нужна новая зависимость;
- изменение затрагивает вход, роли, проверку владельца, защиту от SSRF, протокол worker.

Формат: что случилось → почему → 2–3 варианта с ценой каждого → твоя рекомендация. Владелец может предложить своё решение; оно сравнивается наравне с твоими.

Продолжать «временным» решением до ответа запрещено.

## 7. Тесты

- После каждого изменения: тесты изменённого модуля и его прямых зависимых (команды в `PROJECT_MAP.md`).
- Перед коммитом: весь набор (`uv run pytest`), import-linter (`uv run lint-imports`), `uv run python tools/check_project_map.py`.
- Изменён контракт API — контрактные тесты и тесты обоих клиентов.
- Изменены вход, роли, URL, worker — набор `tests/security`.
- Новый модуль получает тесты на обычный случай, граничный случай и отказ.
- В отчёте: какие команды запущены, что прошло, что упало, что не запускалось и почему.

Красный обязательный тест блокирует коммит.

## 8. Готовые решения с GitHub

Для сложных мест поиск обязателен до написания кода: очередь заданий, адаптер магазина, разбор цен и структурированных данных, защита от SSRF, ротация токенов, перетаскивание, генерация Swift-моделей из OpenAPI, резервные копии.

1. Найди 2–4 зрелых проекта. Проверь лицензию, дату последнего коммита, открытые ошибки.
2. Спроси владельца, есть ли у него свои варианты репозиториев.
3. Сравни в таблице: варианты агента, варианты владельца, решение из плана. Критерии: корректность, безопасность, объём кода, зависимости, лицензия, поддержка.
4. Рекомендуй одно. Если готовая реализация лучше плана — предложи её, а не план.
5. После решения владельца запиши источник и лицензию в `PROJECT_MAP.md`.

Код копируется только при совместимой лицензии и с указанием источника. Кандидаты для первого сравнения: procrastinate, extruct, price-parser, changedetection.io, SortableJS, apple/swift-openapi-generator, schemathesis.

## 9. Порядок работы над функцией

1. **Спецификация.** Проблема, поведение, что не входит, затронутые данные и API, критерии приёмки.
2. **План.** Небольшие сквозные срезы с тестами; обычный путь и отказы. Владелец утверждает.
3. **Сборка.** Один срез за раз.
4. **Тесты.** По разделу 7.
5. **Ревью.** Корректность, безопасность, отказоустойчивость, границы модулей, доступность интерфейса.
6. **Поставка.** Только зелёная версия; миграции, копия, проверка основных сценариев, путь отката.

Автоматически выполнять несколько срезов подряд можно только по утверждённому плану и до первого провала.

## 10. Файлы, которые ведёт агент

- `PROJECT_MAP.md` — обновляется в той же задаче, если изменились модули, связи, данные, API, конфигурация или команды тестов. Только короткие пункты и пути; без кода и секретов. `tools/check_project_map.py` проверяет, что каждый пакет описан, каждый путь существует и указанные зависимости совпадают с графом импортов.
- `FEATURE_STATUS.md` — обновляется после каждой задачи, меняющей функциональность. Одна строка на функцию, без пояснений.

## 11. Отчёт по задаче

Что сделано → изменённые файлы → запущенные тесты и результат → обновлены ли карта и статус → замеченные проблемы вне задачи → вопросы владельцу.
